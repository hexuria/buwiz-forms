How the PDFs were saved
-----------------------
Each run used the real Linux GTK desktop app through `nsh test ./check355-print.test.tsx --target linux` in the buwiz-nsh-2404 container, under Xvfb/dbus-run-session with GSK_RENDERER=cairo and the required safety environment. A scratch, untracked fixture (`nsh/Check355Print.tsx`) seeded the return through the app's own screen-form host APIs (`screen_form_sample_period`, `screen_form_fill`, `screen_form_save`), opened the saved return in the real shell, pressed the real `fp-print` Print preview control, then used the existing test-only Save PDF hook (`testing.savePath`) exposed by the print fixture because the native save panel cannot be driven by the test driver. No Queue control was pressed. No live SFTP mode was enabled.

Environment/deviations
----------------------
- The values were seeded through app host APIs rather than typed one by one in the UI. The return was nevertheless saved first, opened as a saved return in the running desktop app, and printed through the desktop print preview path.
- `WEBKIT_DISABLE_SANDBOX_THIS_IS_DANGEROUS=1` was required inside this unprivileged container: without it WebKitGTK/bwrap crashed with "No permissions to create new namespace" when print preview opened. This was only the scratch container/test environment.
- `pdffonts`/`pdftotext`/`pdfinfo` were not installed system-wide. poppler-utils 22.02.0-2ubuntu0.15 was downloaded with apt and extracted locally under ~/BuwizNsh/poppler-local without sudo; those binaries produced the text outputs.
- before.pdf has 2 pages; after.pdf has 3 pages. The third after page is the Additional Sheet carrying the full taxpayer name/address continuation.
- Nothing was committed or pushed.
