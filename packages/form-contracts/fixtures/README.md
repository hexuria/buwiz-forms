# Form 2551Q renderer fixture matrix

These files are generated by Rust with:

```sh
cargo run -p bir-print --bin generate_render_contract
```

Rust remains authoritative for calculations and validation. The fixtures are
renderer inputs, not an independent source of filing or taxpayer facts.

| Required scenario | Canonical fixture | Expected validation |
| --- | --- | --- |
| Blank/minimum valid draft | `2551q-minimum.json` | None |

| Fiscal-period filing | `2551q-fiscal-period.json` | None |
| Amended return | `2551q-6-rows.json` | None |

`2551q-6-rows.json` remains the pinned visual-reference fixture. Its generated
bytes and SHA-256 are protected by Rust tests because the visual-reference
manifest depends on them. `2551q-10-rows.json` remains the continuation-page
fixture and preserves all ten rows even though the verified XML submission
path currently accepts at most six.

Both schedule fixtures use real January 2018 Form 2551Q ATCs in the official
page-2 order (`PT010`, `PT040`, `PT041`, `PT060`, `PT070`, `PT090`, `PT140`,
`PT150`, `PT160`, `PT170`). Descriptions and rates come from the Rust registry;
the generator does not invent placeholder `PT011` through `PT019` rows. The
taxable amounts are selected so the established 300, 600, ... tax-due series,
page-2 subtotal, and final total stay stable while the rates remain official.

## Remaining source-model blockers

The 2551Q draft now persists optional taxpayer-type and business-start-date
snapshots, and Rust uses them with the filing quarter and PT010 activity to
validate the Item 13 election. The renderer continues to consume only the
validated election value; it does not infer legal applicability from layout
data.

The signature/declaration identities required by the official form are still
not owned by the source model. No fixture invents those values. Those areas must
remain blank or unsupported in renderer evidence until Rust owns the missing
fields and their validation rules.
