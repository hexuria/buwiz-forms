# BIR Forms CUI Port — Audit Verification Brief

**Purpose:** independent verification of an audit of the `buwiz-forms` CUI port
(branch `feat/cui-forms-port`, repo `/home/agent/workspace/buwiz-forms`).
The audit compared all 43 supported BIR forms' *effective* schemas, field
coverage, labels/options, and validation against three sources of truth.
This brief explains **how the findings were produced** so you can re-run or
falsify them. Findings themselves live in `cui/FORM-AUDIT.md` (round 1 +
round-2 sections R-1..R-8); this file is the *methodology + reproduction
kit*.

**Verify at your own risk:** treat every claim below as a hypothesis with a
reproduction recipe, not a conclusion.

---

## 1. What was audited

- App under audit: `cui/` — a native Rust/CUI desktop port of the NSH
  (`nsh/`) BIR forms app. All 43 form codes open through one shared renderer
  (`cui/src/screens/form.rs`) driven by a session layer
  (`cui/src/form/session.rs`) and a schema model (`cui/src/form/schema.rs`).
- Host/schema source: `app/forms/forms-schema.json` (raw extracted schema),
  `app/forms/schema-overrides.json` (~54k lines of `add:`/`move:`/`table:`/
  `hide:`/`label:`/`options:` corrections), `app/forms/conditions.json`,
  `app/forms/screen-1700-v2018.json` (hand-built 1700 replacement schema).
- Effective schema = what `screen_form_schema` host call returns **after**
  overrides. Code: `crates/bir-app-api/src/screen_form_module.rs`
  (`apply_overrides`, `schema_entry`).

## 2. The three ground truths used

1. **Effective schema dump** — the real payload the app renders.
2. **Official XML contracts** — `crates/bir-core/data/official-xml/*.json`,
   generated by running BIR's *official HTA* saveXML loop under jsdom
   (sha256-pinned). This is the authoritative "what keys must the savefile
   contain" list.
3. **betterebirforms/ebirforms** — independent rebuild of BIR's original
   Offline eBIRForms (`src/form/fields/*.json` field ids+kinds,
   `src/form/template/*.json` savefile templates, `src/form/form*.ts`
   validators). Obtained as a codeload tarball (git auth was broken);
   extracted at `/tmp/ebirforms-main` — **may not exist on your machine**;
   re-fetch with `curl -L https://codeload.github.com/betterebirforms/ebirforms/tar.gz/refs/heads/main`.
4. **Validation rule corpus** — `rules/forms/<form-id>/validations.json`:
   2,007 documented rules mined from the official HTA (1,678 carry
   `exact_message`).

## 3. How the effective-schema dump was produced

A temporary (now committed, `#[ignore]`d) test dumps all 43 effective
schemas:

- `cui/src/door.rs::dump_effective_schemas` — calls host
  `screen_form_schema` per code, writes `/tmp/effective-schemas/<CODE>.json`.
- `crates/bir-app-api/src/screen_form_audit.rs::dump_effective_schemas` —
  same via `screen_forms_index`.

Run either with:

```bash
cd cui && cargo test dump_effective_schemas -- --ignored --nocapture
# or in bir-app-api if its deps resolve:
cargo test -p bir-app-api dump_effective_schemas -- --ignored --nocapture
```

Note: `cargo test -p bir-app-api` failed in this environment because two
git-pinned deps (`gpui-component` rev `a0230db…`, `gpui-agent` rev
`dab8599…`) were unfetchable; the `cui` crate builds fine because it
depends on `bir-app-api` with `default-features = false` (agent feature
off). If you have network, both should work.

## 4. How the missing-field diff was computed

Script logic (reproduce in ~30 lines of Python):

1. For each of the 43 codes, load `/tmp/effective-schemas/<CODE>.json`.
2. Collect keys from `parts[].items[].f[].k` and `parts[].items[].keys[][]`
   (schedule rows).
3. Normalize: strip `#occurrence-N` suffixes, strip the `frm…:` namespace
   prefix (keep the part after the first `:`).
4. For official XML, load `crates/bir-core/data/official-xml/<matched>.json`
   `entries[].key`, same normalization. File matching is by lowercase form
   code prefix (watch variants: `1600pt-v2018{,-government,-private}`,
   `1600wp-v2010-atc*`, `2551q-v2018-atc-options` is NOT a form file).
5. `missing = official − effective`, `extra = effective − official`.

Known false-positive classes to filter before believing a "missing" key:
- Workflow/pagination: `txtCurrentPage`, `txtMaxPage`, `txtEnroll`,
  `txtFinalFlag`, `ebirOnline{Username,Secret,ConfirmUsername}`,
  `driveSelectTPExport`, `hPartIITableSize`, `modLabel`, `numOfDays`,
  `numOfMonths*`, `attachment{Current,Total}`.
- Engine-computed hidden keys: `Pg3Pt6*PopLength` (1702EX), `hdnI5TIN4/P2`,
  `hdnRDO` (1707A), `hdnPg1Pt1I7RDO` (1702EX — UI alias for official
  `rdoPg1Pt1I7RDO`, both written by `form_1702ex.rs:878-879`).
- Representation changes: 2550M `AtcCode1..36` bools ↔ 36 `sel` dropdowns;
  `#occurrence-N` duplicate keys.
- Page-2 header *copies* (`txtPg2TIN*`, `txtPg2BranchCode`,
  `txtPg2TaxpayerName` on 1701Q/2551Q): engine/profile-filled duplicates of
  page-1 data — classify as low-impact, but note 2551Q/1701Q are the only
  forms where the block was never extracted into the schema at all.

## 5. Claim-by-claim verification recipes

### R-2 / B-new: 1700 payment details missing (the big one)

Claim: `frm1700:txtPg1I38{Agency,Number,Date,Amount}`, `txtPg1I39{…}`,
`txtPg1I40{Number,Date,Amount}`, `txtPg1I41{…}`, `txtPg1I37Particular`
(17 controls) have no UI field AND the draft model doesn't store them;
engine emits them empty.

Verify:
```bash
# 1. Absent from effective schema:
grep -c 'txtPg1I38\|txtPg1I37Particular' /tmp/effective-schemas/1700.json   # expect 0
# 2. Present in official contract:
python3 -c "import json;print([e['key'] for e in json.load(open('crates/bir-core/data/official-xml/1700-v2013.json'))['entries'] if 'I38' in e['key'] or 'I37Particular' in e['key']])"
# 3. Schema itself admits it:
grep -o 'Part IV Details of Payment[^"]*' app/forms/screen-1700-v2018.json
# 4. Independent repo HAS them as editable fields:
grep -n 'txtPg1I38' /tmp/ebirforms-main/src/form/fields/1700v2018.json
# 5. Engine emits empty: check form_1700.rs official_layout / to_bir_field_map
#    for I38-I41 handling (expected: written as "" or absent).
```

### R-1 refutations (things round 1 got wrong — verify these are truly covered)

- RDO on all 43: `grep -n 'add:.*RDO\|"k": "frm.*RDO\|"k": "rdo' app/forms/schema-overrides.json`
  plus `txtRDOCode`/`txtSpouseRDOCode` in `/tmp/effective-schemas/1700.json`.
- 1707 NoOfShares1: `grep -n 'NoOfShares1' app/forms/schema-overrides.json` → `add:3:0`.
- 1702RT net income: `grep -n 'NetIncome' app/forms/schema-overrides.json` → `add:11:0`.
- 1700 namespace: `crates/bir-app-api/src/screen_form_module.rs` `schema_entry`
  swaps in `screen-1700-v2018.json`; keys are `frm1700:txtPg*` matching
  `official-xml/1700-v2013.json` (note: file named v2013 was generated from
  the v2018 HTA — check `generated_by`/`official_hta` fields).

### R-3 remaining real gaps

- `txtAddress2`/`txtOtherName2` on 1601EQ, 1601FQ, 1603Q, 1604E, 2000,
  2000OT: `grep -n 'txtAddress2' crates/bir-core/src/forms/form_<code>.rs`
  → engines `put("txtAddress2", String::new())` or omit; no schema key.
  Exception 1701Q merges lines by design (`form_1701q_xml.rs` comment);
  1800 auto-splits (`form_1800.rs` `split_address`).

### R-4 required markers vs blocking

- Schema `r` flags: check `"r":` on `txtI5TIN*` in
  `/tmp/effective-schemas/1707A.json`, `txtPg1TIN*` in `2552.json`,
  `txtMonth`/`txtYear` in `2200AN.json` — expect absent/`None`.
- Blocking still occurs: `form_1707a.rs` `tin_is_well_formed`,
  `form_2552.rs` TIN shape check, `form_2200an.rs` `date()` → err.

### R-5 validation coverage (66.6%)

Method: for each `rules/forms/*/validations.json` rule with
`exact_message`, check the normalized message appears in the form's Rust
sources (`crates/bir-core/src/forms/form_<code>{,_official,_xml}.rs` +
`crates/bir-core/src/validation*.rs`). Result: 829/1,245 validate+save
rules matched; full miss list committed at `cui/audit-validation-misses.json`.

**Caveat to check:** misses ≠ missing rules. 1700's misses are largely
item-renumbering (our v2018 screen vs v2013 rules packet). Spot-check
`form_1604f.rs` `remittance_error` and `form_1702mx.rs` basis checks
against `1604f-v2018`/`1702mx-v2018c` validations.json rules before
concluding gaps.

### R-6 renderer findings (UI-layer, verify in `cui/src/`)

- I-13 profile fold cosmetic: `draw_part_items` (`screens/form.rs:1771`)
  iterates all items; `profile_open`/`toggle_profile_fold` never consulted
  for visibility.
- I-14 empty select shows first option: `sel_shown` (`form/session.rs:2126`)
  drops the `CHOOSE` head that `model::select_model` (`form/model.rs:43`)
  builds; `draw_select` (`screens/form.rs:2159`) `unwrap_or(0)`.
- I-15 schedule radio unpickable: schedule `keys` populate `kind_of`/
  `key_index` only (`session.rs:~5090`); `pick_radio` requires `field_of`
  (`session.rs:~1467`). Radio cols exist on 1700 + 1701 schedules
  (Taxpayer/Spouse). `chk` cells work via `s.choose`.
- I-16 schedule totals show sel codes: `cell_read_text` (`form.rs:2345`).
- I-1..I-12 (fold/TIN/rows/errors/maxLength/searchable-select/date-asks/
  item-chip/election-hints/read-only-box/"Y"-value/locked-radios): compare
  `nsh/screens/form/{rows.tsx,schema.ts,controls/*}` against
  `cui/src/screens/form.rs` + `cui/src/form/{session,schema,model}.rs`.
  Helpers exist but are unused: `is_tin_item`, `tin_kind`, `more_open`,
  `toggle_more`, `is_on`.

## 9. Environment notes (so you don't re-debug this)

- **`GH_TOKEN` env var is a stale sandbox token — always `401`.** Unset it
  (`env -u GH_TOKEN`) before `gh` commands; stored `hosts.yml` creds are
  also invalid.
- **The egress proxy (`192.0.2.1:8889`) breaks api.github.com** — it returns
  `401 Bad credentials` even for unauthenticated endpoints. `gh` and proxied
  `curl` cannot reach the API. Bypass with `curl --noproxy '*'` or
  `urllib.request.ProxyHandler({})`. A valid PAT worked this way (secret
  gist: https://gist.github.com/hexuria/69546fd4e2bcd8d53165856c453998f2).
- **This clone has NO git remote** — local-only, nothing to push.
- `cargo test -p bir-app-api` fails here (unfetchable git-pinned deps
  `gpui-component`/`gpui-agent`); run tests through the `cui` crate instead.

  `/tmp/effective-schemas/` (43 files).
