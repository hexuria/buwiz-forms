# shell/desktop: the desktop host (D4)

What makes the app a desktop app: the application menu, the tray and hide-to-tray, the global show/hide hotkey, the updater and the one-copy
guard's wake-up. `App.tsx` mounts `<DesktopHost />` beside the frame; it draws only the About dialog. Off the desktops it does nothing.
Rust half: `src/desktop.rs` (the hooks' mailbox, the one-copy guard, the hotkey combo mapping, module `Desktop`).

## The app menu design (feat/app-menu)
- File > New Tax Profile… (no shortcut; Ctrl/Cmd+N stays New Return…), a last Profiles menu (switcher, current checked, New Tax Profile…; "No taxpayers yet" when empty), and an eBIRForms menu first on Windows and Linux too (its items carry no shortcuts: File/Edit keep them). New Tax Profile… is disabled where the profile panel offers no New taxpayer; other taxpayers are disabled for a non-admin.
- Where the menu shows is `shell/chrome_layout.ts` (pure, tested): macOS the system bar, KDE the panel while NSH reports the menu in Plasma's Global Menu (nsh/desktop `Menu.inGlobalMenu()`, from NSH's `global_menu.rs`; two rows again when the widget goes), Windows and other Linux desktops a 32-point menu row above the toolbar (`shell/MenuRow.tsx`), ☰ in the narrow header under 600.

## Behaviour (and where it differs from the old app)
- ~~`CLOSE_POLICY` (macOS X and Cmd+Q hide, quit in the tray; Windows X and Alt+F4 hide, no Ctrl+Q; Linux X and Ctrl+Q quit)~~: **replaced** by the owner's approved close/quit/hide rules (2026-11-18), `closePolicy(os, prefs)` in `menu_model.ts`:
  - Quit: Cmd+Q / Ctrl+Q really quit on every platform, Windows included (Apple review: Cmd+Q quits out of the box; Quit is always in the app menu and the tray). Super+Q is off on Linux until recorded.
  - Hide: Cmd+H / Ctrl+H hide to the tray with no question. On macOS every hide (Cmd+H, the red button, Cmd+W, the tray's Hide, the hotkey) also takes the Dock icon away: `Desktop.setDockIcon(false)` makes the app an Accessory (menu-bar) app on NSApp, and every show makes it Regular again and activates it: DesktopHost calls `windowShown()` whenever the window's visible state turns true, so NSH's own reopen (the app opened again from the Finder, Spotlight or Launchpad: `applicationShouldHandleReopen` shows the window natively) brings it back too, not only showMain (tray, hotkey, second launch). The policy stays in the app: NSH's reopen only shows the window, and following the visible state covers it. NSH has no run-time switch for this (nsh.json `macos.activationPolicy` is fixed at launch), so `src/desktop.rs` sets it on NSApp itself, as `print.rs` reaches AppKit; a process with no NSApp or one running in the background (Prohibited: real-window tests) is left alone.
  - Close: macOS's red button and File › Close Window (Cmd+W) hide. Windows' and Linux's ✕, Alt+F4 and Close Window (Ctrl+W) ask "Close eBIRForms?" (Quit / Hide to tray, "Don't ask again"; Enter hides, Esc keeps the window) unless a choice was remembered. With no tray icon (`Tray.available()` false: Linux with no StatusNotifierWatcher, GNOME without the AppIndicator extension) it offers Quit and Cancel, Quit is the default (Enter) and it says why; a remembered Hide asks instead, and the hide key, the global hotkey and the menu's Hide minimize the window rather than hide it, so nothing hides into nothing. Settings › Keyboard › Close button (✕) sets Ask / Hide to tray / Quit. A close the system asks for (`closePress` reason `system`) quits without asking.
  - Any quit (menu, key, tray, the close question's Quit, a remembered Quit, the Dock's Quit, a macOS logout, restart or shutdown) warns while returns are Queued (`returnsSending`: the Queued returns of `store.returns("filed")`, which a taxpayer session narrows to its own; 0 behind the gate or the app lock): "N returns are still sending" with Quit anyway / Wait (stay open) / Hide to tray; from a hidden window it shows the window first.
  - The platform's quits: DesktopHost listens to NSH's `Application.on("quitRequest")` and, on macOS, `setQuitRequestOptions({ system: true })`, so the Dock's Quit and a logout, restart or shutdown run `requestQuit` too. Decision for a system quit: nothing sending, the app quits at once and the logout goes on without a word; returns sending, the same warning shows: Quit anyway lets the logout go on, Wait and Hide to tray cancel it (`Application.cancelQuitRequest()`: macOS says the app stopped the logout, and the returns keep sending). Left unanswered, NSH cancels the logout itself before macOS's two-minute limit, so the system is never left hanging; the user logs out again once the returns are sent. Windows' and Linux's session end is a `closePress` of reason `system`, which quits.
  - Keys: Settings › Keyboard (`screens/settings/Keyboard.tsx`) records the quit and hide keys with `ShortcutRecorder`; the app menu's Hide and Quit (and on Windows and Linux the eBIRForms menu's; File's copies carry no key) show them. `keyHolder` refuses a key another item, a platform item, the frame (`mod+l`, `mod+[`, `mod+]`) or the global hotkey holds, and one with no Ctrl/Alt/Cmd. Cmd+Q, Cmd+H and Ctrl+Q cannot be bound by nsh/keymap, so while a box records the menu's Quit and Hide carry them (`CAPTURE_KEYS`) and hand them to the box (`captureMenuKeys`, the recorder's `listen` prop): Cmd+Q can become Hide once Quit has moved (Option+Cmd+Q, say).
- Tray: primary click shows the window, secondary click opens Show / Hide / Quit eBIRForms (an `onClick` stops the primary click from opening the menu); Show is disabled while the window is visible, Hide while it is not. Quit = `requestQuit()`.
- Dropped from the old menu: macOS Services, Edit > Delete (no NSH role). Items with no NSH role are ours (About, Hide, Close Window, Sign Out, Quit, Bring All to Front); the rest are roles. The Shell's own `keymap` chords (mod+b, mod+k ...) stay; a keymap chord wins over the same menu shortcut, so a key never runs twice.
- Window size and place: nsh.json `window.restoreBounds: true` (NSH keeps the placement itself).
- Hotkey: read from `store.systemInfo().global_hotkey` (the page may read only `theme_preference` with `get_setting`), only while the filing chrome is up; mapped by Rust (`Desktop.hotkeyShortcut`, bir-app-api's `hotkey_combo` rules: `KEYS` (a-z, 0-9, F1-F12, the old listener's) and `NSH_KEYS` (space, arrows, home, end, page up and down, punctuation as words like `COMMA`, F13-F20: only this app registers them, so `set_global_hotkey` takes them through `NshHooks::global_hotkey_registrable` and the old shell's rule still refuses them); a combo with no Control, Alt or Command is refused).
- One copy: `desktop::prepare_process` runs when the native module registers. `<database>.instance` is an exclusive file lock, `<database>.instance.port` the loopback port of the running copy; a second launch sends "show" and exits 0 before any window opens; the first copy's `Desktop.poll().activate` shows its window. It is off in a test environment (`EBIR_TEST_ENV`) unless `BIR_SINGLE_INSTANCE=1`; `=0` turns it off. It never writes beside the owner's folders.

## Packaged app updates
- `nsh.json` fixes the feed to hexuria/buwiz-forms and pins its public key. Build with `nsh package`, then publish `latest.json` and `latest.json.sig` from `nsh update-manifest` alongside the update archives. Only the owner supplies the signing secret (`NSH_UPDATE_KEY`). The macOS update archive must contain the signed app.
- Checks start 2 seconds after launch and repeat every 4 hours. Help > Check for Updates… checks immediately. A dev run has no feed; a `mas_build` disables the driver, the menu item and automatic update settings.
- Direct downloads (macOS DMG, Windows Setup.exe, Linux tarball) can self-update when NSH reports that the installation is writable. The MSI, MSIX, deb, rpm and Arch packaging steps must put an empty **`ebirforms-no-self-update` file beside the actual installed executable** (not beside a launcher or symlink). These installs offer a link to GitHub Releases, even if writable. Do not include the marker in the direct downloads or updater archives.
