## The reactive rule
A component function runs ONCE. Only JSX expressions and closures that read a signal run again.
- Read props and signals inside JSX or a closure: `<Text>{props.title}</Text>`, `const label = () => props.a + count()`.
- Never destructure props (`function Row({title})`, `const {a} = props`) and never copy a read into a body `const`: it goes stale and nothing reports it.
- Write signals with `.set(v)` or `.update(fn)` and always a NEW array/object. `items().push(x)` does nothing.
- `<Each of={list()} key={(x) => x.id}>{(x) => ...x().field}</Each>`: row gets accessors (`x()`). `If` and `Each` are globals. No `.map`, no `cond && <A/>` for stateful parts.
- Long or growing lists: `List` (virtualized, recycled): no signals, no `const t = row().title` in a row; per-item state lives in data keyed by id.
- Import the JSX type: `import type { JSX } from "nsh"` (tsc fails with "Cannot find namespace 'JSX'" otherwise).

## Non-negotiables (NSH skill)
Never invent an API: look it up in `.nsh/types/nsh/*.d.ts` (props, events) or the docs below, and cite it. One owner per state (a screen's draft is
its signal; shared state is a module store with private signals). Text only inside `<Text>` (a bare string in a View is a build error; a string
child of a Button or a number in a View shows NOTHING and no tool reports it). Use Button/Dialog/Sheet/Menu/Select/Switch/Input from `nsh/base`,
never a View with onPress. `nsh/base` parts draw nothing until styled (a Switch with no trackClass/thumbClass is invisible and its test passes):
look at it. A decision the system needs at once is a prop (`disabled`, `popOnBack`), never a callback. Handlers get ONE object (`onChange={({value}) =>`).
No DOM, no Node, no npm UI: imports are `nsh`, `nsh/base`, `nsh/desktop`, `nsh/mobile`, `nsh/test`, relative files, `ebirforms/native`, and
buffer console crypto fs/promises net os path process url websocket zlib. Screens use `nsh/ui`/`nsh/shell` and `nsh/bir`, never raw base or the raw module.

## The Rust bridge
Specifier `ebirforms/native` (crate `nsh-app-ebirforms`, `src/lib.rs`). Today: `Door` (next section) and `Bridge.ping(): string` (`"pong"`), used by `screens/base/ThemePage.tsx`, tested in
`ThemePage.test.tsx` and `src/lib.rs`. Types are generated into `.nsh/types/ebirforms/native.d.ts` by `nsh check` from the Rust signatures and doc comments.
- Rust signature decides the call: plain `fn` = synchronous, runs in the TSX call, `Result` Err becomes a thrown Error; `async fn` = Promise; `cx: &mut ModuleCx` = op.
  `#[module] struct` + `#[module] impl`, register in `#[native_module]` with `registry.module::<T>()`. Doc-comment every export (`///` on the struct, never on the impl block).
- Rust state is invisible to the reactive graph: mirror what a screen shows in a signal and update it from the return value.
- `nsh-base` is NOT a dependency now (unused-dependency warning); add it to Cargo.toml only when Rust code uses it. All `nsh-*` deps are PATH deps on the one checkout.

## The door (`bir/`, `src/door.rs`): how a screen reaches the Rust brain
Import ONLY from `bir` (relative, e.g. `import { bir, type Taxpayer } from "../../bir"`; a directory import works). Never import `Door` from `ebirforms/native` in a screen.
- `bir.<host_function>(...)`: 116 typed wrappers, named exactly as the Rust host functions and the old app's `bir.<name>(` (snake_case). Sync ones return the value, async ones a Promise
  (`screen_form_open`, `screen_form_validate`, `import_archive`, `export_profile`, `cloud_account_*`, inbox ones). A host error is a thrown Error whose `message` is the host's sentence, unchanged
  (the old `errorText` regex is not needed). Every type (`Taxpayer`, `ScreenFormOpened`, ...) is exported from `bir` too. `doorStatus()` = `{ sending: "live" | "dry_run" | "mock" | "relay" | "refused", databasePath, testEnvironment }`.
- 18 host functions the old app never calls are NOT wrapped (`NOT_WRAPPED` in `bir/functions.ts`). Need one? Add its name to `bir/extra-functions.txt` and run the script below. Generated files (never edit): `bir/types.d.ts` (from the Rust declarations; a Rust test fails while it is stale) and `bir/functions.ts`.
  Regenerate with `bash nsh/bir/regenerate.sh` after bir-app-api's declarations change.
- Tests: `import { createDemoTaxpayer, DEMO } from "bir/testing"` (relative) gives Juana Santos (`DEMO.tin` = "00012345300000" as host functions take it). In a test environment (`EBIR_TEST_ENV=1`, which every recipe sets) the
  door makes a fresh scratch database in the temp folder per engine thread: each `open()` and each test FILE starts EMPTY, tests inside one file share it. `useDatabase(path)` names a file instead (before the first call; guarded).
  Real data: `BIR_DATABASE_PATH=~/BuwizNsh/agents/<track>.db` (raw `nsh test` / `nsh run`; `just nsh-test` unsets it). `bir/DoorProbe.tsx` + `.test.tsx` is the pattern for a mounted component calling the door.
- The door boots itself on the first call of an engine thread (old host's order: hooks, send guard, database guard, `prepare_launch`, database + submission worker, updater hook). A normal desktop release uses the shared filing transport.
  In debug, test, agent and mobile launches the guard removes `BIR_SFTP_LIVE` and forces `BIR_SFTP_DRY_RUN=1` unless a guarded local mock is selected. Database guard: no path inside the owner's Group Container, `~/BuwizNsh/data`,
  `~/BuwizNsh/migration` (symlinks and `..` resolved; also by device+inode, so `/System/Volumes/Data/Users/...` firmlinks, other cases and hard links are caught; the home folder is the account's own from getpwuid, not `$HOME`), checked before every call. Debug builds always set `BUWIZ_NO_KEYCHAIN=1`; release leaves it to the caller. `EBIR_TEST_ENV` is read as bir-core reads it (`1|true|yes|on`, `bir_core::db::test_environment`). `shutdown()` (from `bir`) is the quit path (stops the worker, checkpoints): call it once on quit and use the door no more (a retention thread keeps the database and its owner lock until exit, as in the old host).
- Hooks (`src/hooks.rs`): file panels are NSH's own dialogs. App menu, chrome, and updater are in D4 below. See "Print preview" at the end and "NSH app" in `docs/agent.md` for opt-in agent control (`just nsh-agent-check`).

## Tests
Files: `*.test.tsx` / `*.test.ts` anywhere (hidden dirs skipped). Only that suffix counts: `nsh test x.tsx` on any other name runs it as an app entry from stdin.
```tsx
import { expect, open, test } from "nsh/test";
test("phone", async () => {                       // default viewport 390x844, platform "ios", light
  const app = await open("../../App.tsx");        // path relative to THIS file
  await app.press("role:button[Save]");           // also text:Add, label:Close, id:testID, "text:/^Buy/i", "id:x >> role:button"
  expect(app.texts()).toContain("Saved");
});
test("desktop", async () => {
  const app = await open("../../App.tsx", { width: 1440, height: 900, platform: "macos", colorScheme: "dark" });
  await app.setViewport(500, 700);                // resize live; app.setColorScheme("light") too
});
```
- Every screen needs one phone test (default) and one desktop test (width>=1440, platform "macos"). `app.waitFor("text", {state:"gone"})`, `app.type(sel, s)`,
  `app.value(sel)`, `app.enabled(sel)`, `app.back()`, `app.onDialog(d => "Remove")`, `open(.., { storage, network: {"GET url": {body}}, clock: {} })`.
- A press on a text finds the button around it. Selectors must match exactly one view for actions. Test with the demo taxpayer (Juana Santos, TIN 000-123-453-00000) only.
- Headless proves behavior, not looks. Pure logic tests (no `open`) are fine (`theme/theme.test.ts` imports JSON). In test files `process.env` shows only COLORTERM/LANG/LC_ALL/TERM and `process.cwd` does not exist.
- `nsh test` hardens the runtime (no eval); `--filter "name"`, `--trace` (mount batches per step), `--junit file.xml`. Default test timeout 30 s.
- **Slow machines (the CI runner is 3 to 4 times slower).** Headless, one JS call has 2 s ("interrupted"), a file's or bundle's load has 10 s, a new app has 5 s to render. The host parses the schema files on the first form call of a process (about 0.1 s in a debug build) and builds each form's schema on its first use (0.05 to 0.15 s); it used to build all 43 at once (1.2 s here, over the 2 s on CI: `screen_form_module.rs` `FormSchema`, `KeyPlaces`). `warmForms()` (`bir/testing.ts`) at the TOP LEVEL of a test file or fixture still moves the parse out of the first test; never call it inside a test. Never count ticks in a fixed sleep: wait for the condition (`until(...)`), and wait for a sheet or popup to be gone before pressing what it covered. A long `app.scroll` runs in real time unless the app is opened with `clock: {}`.

## Real-window screenshots (light and dark, wide and narrow)
Write `shots/<name>.test.tsx` like `shots/base.test.tsx`: loop `LOOKS` from `shots/shoot.ts` (wide-light/dark 1440x900, narrow-light/dark 390x844, platform macos), `open` each,
drive the screen, `await shoot(app, "<name>-<look>-<step>")`, scroll with `app.scroll("id:page-scroll", 5000)` (give the Scroll a testID). Then `just nsh-shots <name>`.
- It runs `nsh test <file> --target macos` from `~/BuwizNsh/evidence/<name>/` because PNGs are written relative to the current directory. Never save PNGs in the worktree.
- Windows open in the background (no focus steal), one per test, on a secondary display if there is one. Pictures are Retina: 2x pixels (1440x900 -> 2880x1800).
- `app.screenshot` rejects headless ("a screenshot needs a real platform"); `shoot()` swallows exactly that, so shots tests also pass in `just nsh-test`.
- Look at the PNG (Read tool shows images). A tool that passes does not prove it looks right. `nsh run` window size is not settable for this app (the flag had no effect; 900 pt wide seen).
- nsh.json `window` (defaultSize/minSize) is for packaged apps; the dev host and tests size windows from `open()`.
- Timing: a real-window `app.press` on a control inside a Scroll first scrolls it away from the edge and waits for the scroll to stop
  (about 1.8 s on the form page's `fp-print`/`fp-check`; a plain overlay button lands in about 0.15 s). So never time a feature from
  the press: put a mark in the handler and measure from there. (Print preview: press-to-sheet read 2.1 s, the app's share was 0.4-0.9 s.)
- Every nsh test or shots run goes through `~/BuwizNsh/tools/bin/nsh-serial <command>` when more than one agent is working: runs that
  overlap disturb each other, and it stops a test window left behind without its runner.

## Pitfalls hit so far
1. This machine's `cargo` is huacnlee/cargo: it IGNORES CARGO_TARGET_DIR and prints "ignoring the configured target directory" on every command (benign). Real builds live in
   `~/.cargo/targets/nsh-app-ebirforms-*`, host binaries in `nsh/.nsh/rust/target` (about 380 MB, ignored); `~/BuwizNsh/target-nsh` stays unused. Other benign noise: "patch nsh-bundler was not used" (generated .nsh/rust) and an `ld: __eh_frame section too large` linker warning on the macOS host.
2. `nsh init` derived the specifier from the folder name (`nsh/native`); it was renamed by hand to `ebirforms/native` (lib.rs attribute + package name). Never rename again: it breaks every import.
3. Cargo.toml points at the NSH checkout by ABSOLUTE path; a clone elsewhere (CI) needs that path adapted. Parked for the owner.
4. A `.tsx` file passed to `nsh test` without the `.test.` suffix is an app entry: it creates a stray `.nsh/` beside it and looks for `nsh-macos-host` in tools/bin. Delete the stray folder.
5. The type-check success line is hidden unless `-v`; `nsh check` still exits 1 on errors.
6. Widths, heights and platform in `open()` only: iOS/Android targets reject them (`ERR_NSH_TEST_UNSUPPORTED`); headless is iOS-like unless you pass `platform`.
7. Unused imports are dropped by TS; a font or asset imported for its side effect must be a bare `import "./x.woff2"`.
8. Do not run a long `nsh run` inside a script you await: it never ends. Start it detached and stop it with SIGINT to the `nsh run` pid (it closes the window).
9. The `ThemePage` is a throwaway preview: `App.tsx` is the frame now (next section); the old switch lives on as `BasePreview.tsx` and as the dev pages `kit`/`theme`.
10. Date code takes the clock as a parameter (`daysUntil(iso, now)`, `periodOptions(..., now)`, `loadDashboard(store, at)`). Tests build local dates with `new Date(y, m, d)` and SQLite timestamps at midday UTC, so they pass in every time zone (the old code reads those timestamps as UTC and shows the local day).
11. A sync host call blocks the engine: the first `screen_forms_index()` builds the form library (about 1 s in a debug build). `app.press` can return before a slow press handler ends: `await app.waitFor("text:...")`, never `expect(app.texts())` right after.
12. Host functions take JSON: `undefined` arrives as `null` (so `get_setting(undefined)` says "got null"), amounts and ids are numbers, the draft is an opaque `object` you pass back unchanged from `screen_form_open`/`screen_form_fill`.
13. The database slot is per engine thread, and one database file has one owner lock per process: two engines on the SAME `BIR_DATABASE_PATH` in one test run refuse each other. Leave it unset and let each test get a scratch file.
14. UI kit (`ui/`): screens import from `ui/index.ts`, never nsh/base. Gallery and states: `screens/base/KitPage.tsx` (the dev page `kit`: palette "UI kit"; the kit's own tests and shots open it through `BasePreview.tsx` with `ui/harness.ts`, not through the frame). `TOUCH` (`!platform.desktop`) picks 44-pt targets.
15. nsh/base's Select/Combobox list filters by ONE run of text in the title (crates/nsh-base/src/listbox.rs), even with a controlled `query`: "east mak" matches, "050 makati" does not.
16. A Select's/Menu's/Combobox's `testID` names the base view, not what a press opens: give the trigger element its own testID (`kit-dropdown-trigger`).
17. State variants: `hover:` and `focus:` beat `selected:`; keep a selected fill with `selected:hover:bg-x selected:focus:bg-x`. A Calendar/DatePicker without `renderItem` shows weekdays as 0-6.
18. Headless: `keyboard.press("left")` does not move an input's caret, Escape does not close a Dialog (use `app.back()`): test mid-text edits on the pure mask (`ui/mask.ts`).
19. `app.scroll` throws past the end ("at X of Y"); real-window tests over 30 s need `test(name, fn, 120_000)`. `just nsh-test x` paths are relative to nsh/; a `--filter` with spaces is split by just.
20. Never spread props into a kit component (`{...props}`): pass each prop (`label={props.label}`) or the props object itself, so reads stay live.
14. A real-window run (`--target macos`, `just nsh-shots`) serves assets (fonts, icons) only from the folder of the entry `open()` names, down: an entry in a subfolder gets HTTP 404 for `theme/fonts` (registerFont throws: "the app threw: asset://...woff2") and blank icons. Headless runs do not show it. Shots fixtures live at the nsh root (`FormShot.tsx`).
15. FIXED (U1): the kit's `<Toaster />` layer used to take presses across the bottom of the window, so a floating bar under it (the form pill) got none. An `Overlay` with no anchor is a fixed box that includes its padding and takes presses; a full-width layer needs `style={{ pointerEvents: "box-none" }}` (style-reference.md), which the Toaster now has: a bar under it is pressable with or without a toast, the toast's card and Undo still work (`ui/toaster.test.tsx`, phone and desktop, headless and `--target macos`). Lift toasts above a bottom bar with `<Toaster bottom={96} />` (default 20, plus the safe area). The form fixtures (`FormShot.tsx`, `screens/form/FormPagePreview.tsx`, `FormPageHeavy.tsx`) mount it again, on a `bg-card` root like the frame's surface; the page itself paints no background.
16. `position: sticky` is the class `sticky top-0` on a child of a `<Scroll>` (tailwind-reference.md): it sticks while its parent shows. Do not put `overflow-hidden` on that parent. `pointerEvents` is a style key (`style={{ pointerEvents: "box-none" }}`), not a prop; `onLayout` gives `e.bounds.size.width`.

## F17: the global hotkey is a shortcut recorder, not a dropdown
- **The part.** `ShortcutRecorder` (`ui/shortcut.tsx`, gallery "Text entry" in `screens/base/KitPage.tsx`): `value` is a keystroke as nsh/keymap names it ("ctrl+alt+e", modifiers in the order ctrl, alt, shift, cmd) or "", `onChange(keystroke | "")`, `label`, `accepts`/`unacceptable` (a rule and its words), `error` (under the box), `onRecordingChange`, `width`, `testID` (the box; `-clear`, `-hint`, `-note`, `-error`). It knows nothing of eBIRForms' combo language. Idle: the chord as the platform writes it (`keymap.label`: "⌃⌥E" / "Ctrl+Alt+E") and an x ("Remove shortcut"), or "None" and "Click to record". Recording: accent border and ring, "Type shortcut", a bubble under the box (an anchored `Overlay`, so the row does not move) with "Esc to cancel · Delete to remove" and, after a refused chord, the words in the danger tone. A chord ends it; Escape, Tab or a press anywhere else (`Overlay` `onPressOutside`: the anchor, the box with its x, does not count; it works headless through `app.press`) cancels; Delete or Backspace removes the chord (asks nothing when there is none).
- **The keymap trick.** NSH has no raw key-down in TSX, so while recording (and only then) the part binds every chord a person could mean in ONE `keymap.bind(record, { when: "always" })`: each subset of ctrl, alt, shift, cmd with a-z, 0-9, f1-f12 (768; F19 widened it to 76 keys, 1216) plus escape, backspace, delete, and a second bind of tab and shift+tab with `passThrough`. The handler gets `{ keystroke }` as written, so one spelling comes back. Bare keys and Shift+key are bound too, so the box answers ("Add Control, Option or Command.") instead of staying silent. Unbound when it ends and in `cleanup`. A binding made in an event handler is NOT removed with the component: the part removes its own.
- **Reserved keys.** `keymap.bind` with a record checks every key before it binds any and throws for one the platform keeps (macOS: cmd+q, cmd+h, alt+cmd+h, cmd+m, ctrl+cmd+f; elsewhere ctrl+q, alt+f4, f11), so the first recording finds them by halving (`ui/chords.ts` `bindAvailable`, about 50 calls) and keeps the answer (`offered`); later ones bind the rest in one call. A reserved key is simply not offered: it still does what the system or the app does with it (Cmd+Q still hides to the tray).
- **Timing, real macOS window (debug host).** First recording (the halving) 15 ms to bind; every later one 2 to 4 ms to bind, 0.1 ms to unbind. The naive way, one `keymap.bind` per chord in its own try/catch, took 10 to 15 ms to bind and 17 to 22 ms to unbind (each call sends the platform the whole table). All under 30 ms.
- **The stored combo.** `lib/settings_model.ts`: `comboToKeystroke(combo, os)` ("control+alt+E" is "ctrl+alt+e"; a bare key takes the HOST's default modifiers, `system_info().os`: control+alt on macOS, super+shift elsewhere, as `hotkey_combo::split_combo`; unknown words ignored; null for no key), `keystrokeToCombo` (cmd is "super"; order control, alt, shift, super; null for no modifier, "mod", or a key outside A-Z, 0-9, F1-F12), `hotkeyRegistrable` (the door's rule: Control, Alt or Command), `modifierWords(platform.os)`, `hotkeyProblem(status)`. Round trip tested for all 15 x 48 and the four old presets (`hotkey_presets` is still sent by the host and no longer read here; the old app reads it). `hotkeyChoices`, `OFF`, `hotkeyOptions`, `hotkeyLabel` are gone.
- **The global hotkey fires while recording.** The registered chord is the system's, so pressing it to record it would hide the window. `holdHotkey()` (`shell/desktop/hotkey_state.ts`, exported by `shell/index.ts`, also `hotkeyStatus()`) is a counted hold: DesktopHost's effect reads the combo as "" while one is on, so the chord is given back, and takes the stored one again when it ends. The part calls `onChange` BEFORE `onRecordingChange(false)`, so the new chord is taken, not the old one first. `hotkeyStatus` lives in that leaf module (no cycle: Desktop.tsx imports `screens/settings/cloud`); where there is no desktop host it stays "off" and nothing extra shows. Computer.tsx says "Another app is using this shortcut. Pick another one." (refused) or "This computer cannot register that shortcut." (invalid) under the box; a refusal from the host's `set_global_hotkey` is a toast and the box shows the stored chord again.

- **Where.** In the Import card under "Import data": "Import from BIR eBIRForms" (`screens/settings/EbirFormsImport.tsx`, rows put straight into the Card as a fragment so the kit's hairline separates them; under 600 the row is a `StackRow`, button under the words). State is `screens/settings/legacyState.ts` (module signals; `app.onSessionChange` lets a held scan go). Phases: idle, scanning ("Reading…"), review (counts, "Not read" list capped at 12 + "and N more", Cancel / Import), importing ("Importing…"), done (counts, Done), problem (an empty folder, not an eBIRForms folder, a host error; OK). Only who sees "Import data" sees it (the `import` row of settings_model).
- **Host verbs** (`crates/bir-app-api/src/legacy_import_module.rs`, registered into the one `bir` module, wrapped through `bir/extra-functions.txt`): `legacy_standard_folders()` (Windows' standard places, `discover_legacy_roots`; empty elsewhere), `legacy_scan_folder()` (async: the host's folder dialog, `Hooks::prompt_for_folder`, NSH's `OpenDialog::folders()` in `src/hooks.rs`), `legacy_scan_standard(index)` (looked up again), `legacy_import(scan)` (sync, under `with_database`; the page calls it through `store.write` so every cached read drops), `legacy_scan_cancel()`. The page never passes a path: a string argument is refused. The scan is held per engine thread with the folder's file list (path, size, mtime) and the database path; the import refuses with no scan, another scan's number (that newer scan is kept), a changed folder or another database, and otherwise lets the scan go whether it imports or fails. A database restore lets it go too, on both paths (`reset_database`, and the in-place swap in `restore_staged_database`), and the page ends its review (`legacyDatabaseReplaced`). A dismissed folder dialog puts the card back as it was (a result stays readable); a lock or sign-out during the review or in the frame before the import lets the scan go and the import does not run. The import itself is one transaction in `apply_legacy_migration`: a failure part-way leaves the database as it was. File names the page gets (`skipped[].file`, `source_file`) go through `shown_file_name`, which drops the `#address#` part an e-mailed copy's name carries; a folder-dialog answer that arrives after a lock or sign-out is dropped (`session` in legacyState.ts). Known limits: the scan and the import run on the engine thread (a folder of thousands of returns holds the window while it is read); the host checks the account gate, not admin rights (the page's `adminOnly` row does, as for `import_archive`).
- **Filed returns show in Filings since F20** (the section below). They land in `legacy_filed_returns`; `list_legacy_filed_returns` reads them back for one branch's TIN, and `get_form_filing_progress` counts them as filed (no page calls it: see F20, "The counts").

## F20: what the import brought in shows in Filings ("Filed in BIR eBIRForms")
- **The verb.** `list_legacy_filed_returns(tin)` (`crates/bir-app-api/src/legacy_import_module.rs`, wrapped through `bir/extra-functions.txt`): a sync read behind the account gate, `with_reader` as `list_taxpayers` (a locked app refuses with the gate's sentence; the reader connection does not wait for the submission worker; `reader_tests.rs` times it with the polled reads). It takes ONE branch's TIN (12 to 14 digits, dashes allowed; a bare 9-digit root, another taxpayer's or another branch's TIN answers `[]`) and answers `{ id, form, form_code, period, amendment_version, email_copy, source_file, imported_at }[]`, oldest import first. `form` is the resolved form id when there is one (`1601Cv2018`), else the identity as stored; `form_code` is this app's code for it (`1601C`), resolved as `get_form_filing_progress` resolves it, null when there is none; `period` is as the file's name wrote it (`062025`, `2026Q1`, `122026Q1`, `2025`, `03152026`); `email_copy` is a boolean; `source_file` is the old program's file name without the `#address#` part an e-mailed copy's name carries (`shown_file_name`), so no e-mail address reaches the page; `imported_at` is SQLite's UTC text. No bytes, no field values: `Database::list_legacy_filed_return_summaries_for_tin` (bir-core, new, beside `list_legacy_filed_returns_for_tin`) selects those columns only, so a list of hundreds never loads the stored files. Rust tests: the fixture import gives its three rows, another TIN none, the locked gate refuses, the answer's keys are exactly those and hold no name, address or stored bytes.
- **Where, and why Filings.** Filings is where a person looks for what was filed; the taxpayer page (Profile, Forms, Templates) is about what a taxpayer files from now on and has no list of returns. The group is `screens/filings/LegacyGroup.tsx` (pure rules `legacy.ts`, so not a `legacy.tsx`: pitfall 26) under the board (wide, a page of 720 or more) or under the list (narrow, on the All tab only: a status tab is this app's statuses). It lists the taxpayer in view, `app.taxpayer()`, across every branch (one `store.legacyFiled(tin)` read per branch, key `legacy_filed:<tin>`, narrowed by `store.canSee` like every taxpayer read; `legacy_import` goes through `store.write`, which drops it). Filings itself lists every taxpayer's returns, so the group says whose they are ("Imported from the old program for Juana Santos. Records only: they cannot be opened or sent."); switching the taxpayer in the sidebar switches the group. It shows only while nothing narrows the page (no search, no filter, no Home tile's month): those speak of this app's returns, which the old program's are not. No rows: nothing is drawn (no title, no empty box). The lines are not pressable and carry no Cancel queue; they are not in `store.returns`, the board's columns or its "N returns".
- **A line.** "1601C Jun 2025" (the code, else the old program's name for the form, then the period as Filings names periods: Jun 2025, Q2 2025, TY 2025, Mar 15, 2026), the chips "Amended (v2)" and "E-mailed copy" where they apply, the branch's name when it is not the head office, and "Imported Nov 17, 2026" (right on a wide page, under on a narrow one). Newest period first, an amendment before its original. `legacyPeriodLabel` reads a period as `legacy_return_period` (bir-core `drafts.rs`) reads it for the counts: a quarterly form's month falls in its quarter, an annual form's is the year; the frequency is `store.catalog()`'s (`forms_catalog`, whose "OpenEnded" is as needed), not the screen index, because the counts use the catalog.
- **The counts.** `get_form_filing_progress` counts an imported return as filed, and NO page calls it (nothing in the old shell or in NSH does: only bir-core tests). Every filed count a page shows is made from the app's own returns: Home's "Filed this month" and "N of M filed this year" (`list_returns("filed")`, `deadlines_between`), Filings' columns and "N returns", Calendar's status chips. None includes an imported return, so no count has a row hidden behind it that this list could not show. The two DO disagree the other way, and nothing was patched around it: after the fixture import, `get_form_filing_progress(tin, "1601C", 2025)` has June as Submitted while `deadlines_between` still lists "June 2025" as Not started (it will read as overdue on Calendar and Home, and `N of M filed` leaves it out) and `list_returns("filed")` is empty. Also: a row whose form the registry does not resolve, or whose period cannot name a period of its form, is listed here and never counted as filed; and a return filed with an all-zero TIN is imported into the table (the review and result count it) but belongs to no taxpayer, so no group lists it.
- **Tests and fixtures.** `screens/filings/legacy.test.ts` (pure: periods, order, lines), `LegacyGroup.test.tsx` (store reader and scope; desktop and phone: rows, none, the other taxpayer, read-only, filters stepping aside, tabs), fixture `FilingsDemo.tsx` param `legacy: "rows" | "second"` (swaps `bir.list_legacy_filed_returns` for made-up demo rows: an import needs the host's folder dialog, so a page test cannot make one; without the param the host answers for real: none), shots `shots/f20.test.tsx` (`just nsh-shots f20`, ~/BuwizNsh/evidence/f20).
