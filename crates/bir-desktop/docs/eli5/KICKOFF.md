## Phase 0 — ask before building (stop here and wait for answers)

Ask the maintainer these, one message, numbered. They are the open points in
PLAN-v1-forms-eli5-brief.md §1.C plus two raised by the 2551Q page. Do not
proceed to Phase 1 until each has an answer or an explicit "use the proposal".

1. First-wave forms. Proposal: the ten with typed models, in this order —
   2551Q (done), 1601C, 0619E, 0619F, 0605, 1701Q, 2550Q, 1701, 1702RT, 1702MX.
   Then the other 33 rules bundles? Or a different order?
2. Profile versions ledger. When the COR tab and the effective-dated versions
   go, what answers "which profile applies to period X"? Proposal: the
   per-year profile clone *is* the version — one per tax year, a lookup, no
   effective-date arithmetic. (Today 2551Q is blocked precisely because the
   test profile has zero confirmed versions; 1601-C never looks at them.)
3. Templates. Do per-form templates live on the form (shared across years,
   overridable), or on the profile-year? Proposal: on the form.
4. Storage of the year's chosen forms. Keep the existing `per_year_forms`
   table (source = Manual only) as the store that the dashboard and deadline
   calendar already read, or fold it into the profile-year?
5. Queue / XML / receipts. Nothing in `background_cron.rs`, `db/drafts.rs`,
   or the `*_xml.rs` writers should read the profile flags that are being
   removed (VAT router, withholding flags, excise, entity flags). Confirm we
   may delete them once a grep shows the writers only read the draft.
6. Sections. Follow the paper form's Parts / Schedules exactly (as the 2551Q
   page does), or regroup where the paper layout is awkward on screen?
7. Page-2 repeats. 2551Q repeats TIN and taxpayer name on page 2 (five
   "auto-copied" fields). Show them in the app page as read-only, or hide them
   and only write them into the XML?
8. Field labels. fields.json has keys (txtTIN1, registeredName…), not labels.
   The 2551Q page uses a hand-written item→label map. Accept a hand-written
   map per form, or should labels be extracted from the frozen HTML by
   tooling first?

## Phase 1 — the nine remaining per-form pages

For each form, in the agreed order, extend `form_page.py` with that form's
SECTIONS (paper-form Parts / Schedules → item numbers) and LABELS (item
number → label), then run:

    python3 crates/bir-desktop/docs/eli5/tools/form_page.py <rules-id> <frozen-bundle> \
      crates/bir-desktop/docs/eli5/forms/<CODE>.html

rules-id and bundle come from `ls rules/forms` and `ls html-frozen` (e.g.
1601c-v2018 / 1601c-2018, 0619e-v2018 / 0619e-2018, 0605-v2003 / 0605-1999).
The script prints "drawn N / field_count" — it must say OK for every form;
never hide a mismatch by dropping fields. Derive sections and labels from
the frozen HTML and fields.json, not from the current Rust view in
crates/bir-desktop/src/views/form_<code>_view.rs (that view is the subset
V1 replaces).

Per form, add one line to a table in
crates/bir-desktop/docs/eli5/forms/README.md: code, revision, fields drawn /
field_count, calculations, validation rules, and anything the code could
not answer (as a question, not a guess).

Commit per form (`docs(eli5): <CODE> field page`), push to
`gol/eli5-v1-forms`. Present the links after every three forms and wait for
comments before the next three.

## Phase 2 — the build plan (after Phase 1 is reviewed)

Only when all ten pages are accepted: write PLAN-v1-forms-build.md — the
ordered work items to reach V1 as drawn in 01-what-v1-becomes.html, each
with the files it touches, the tests that prove it, and what gets deleted.
Suggested order: (1) validation gating, (2) one page layout for every form
driven by fields.json sections, (3) profile-year + tax-year selector,
(4) user-chosen forms per year and removal of the inference flags/logic,
(5) COR/OCR removal, (6) templates, (7) delete the nine old views. Do not
start coding in this phase; the maintainer reviews the plan first.

  ~/Library/Group Containers/group.dev.goldcoders.bir/ and never set BIR_SFTP_*.

- Commit messages: conventional prefix, body says why; no AI co-author trailers.

  `gol/eli5-v1-forms`.
