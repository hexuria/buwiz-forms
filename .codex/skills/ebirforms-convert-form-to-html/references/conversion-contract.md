# Conversion Contract

Lock one canonical form code and exact revision before implementation.

## Required evidence

| Area | Minimum proof |
|---|---|
| Source | Official URL/file, SHA-256, revision, page count, paper geometry |
| Domain | Typed Rust draft and primary/corroborated formula evidence |
| XML | Import/export round-trip including repeatable rows and optional fields |
| Lifecycle | Persistence, validation, queue/submission, carry-over where applicable |
| Contract | Rust adapter plus minimum, normal, long-value, validation-edge, maximum-capacity fixtures |
| Layout | Exact-revision React component, scoped CSS, spec, deterministic pagination |
| Artwork | Exact embedded seal/logo objects; decoded PDF417/QR payloads, zero-difference module matrices, inline vectors, live bundled-font captions, or an audited explicit no-symbol result |
| Visual | Pinned blank references, filled goldens, critical-region and full-page results |
| Native | Same document proves preview, print, direct PDF, clipping, offline package behavior |

## Evidence policy

Accept official form instructions, official XML/schema material, confirmed eBIRForms behavior, or multiple independent implementation samples. Record conflicts. Never promote an inference from a single payload into authoritative tax logic.

Represent unknown semantics explicitly and fail closed. Do not silently truncate rows or strings to make a preview fit.

## Fixture matrix

- `minimum`: all legally optional values absent.
- `normal`: representative complete filing.
- `long-value`: maximum valid names, addresses, email, descriptions, and amounts.
- `validation-edge`: missing/conflicting applicability and invalid boundaries.
- `maximum-capacity`: every repeatable schedule filled to its verified limit.

Fixtures must be generated from Rust and remain deterministic. TypeScript may validate and render them but may not author tax results.

## Promotion

Keep the route `disabled` until the component and contract exist. Use `experimental` only for an explicitly labeled development preview. Set `html_only` and `release_ready` only after contract, formula, XML, layout, visual, native, packaged-offline, and no-legacy evidence all pass.
